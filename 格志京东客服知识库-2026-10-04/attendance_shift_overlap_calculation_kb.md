# 考勤机共同班次与自动班次检查知识库

## 1. 两层时间必须分开

- 员工真实班次：不同团队的真实上下班时间可以重叠。
- 机器自动班次：机器不能直接输入互相重叠的自动班次。
- 当真实班次重叠时，先告知客户机器限制，再尝试计算非重叠的共同班次，让多个团队共享自动打卡栏位。
- 共同班次只用于机器自动定位，不取代各团队的真实排班、迟到或早退判断边界。

## 2. 共同班次计算

```text
共同班次开始 = max（各重叠班次的上班时间）
共同班次结束 = min（各重叠班次的下班时间）
共同班次 = 重叠开始时间–重叠结束时间
```

- 如果共同开始早于共同结束，存在有效共同班次。
- 如果共同开始不早于共同结束，不存在有效共同班次，不能强行合并。
- 跨夜班次先放到连续时间轴计算，例如次日02:00按26:00参与计算，对客仍显示为次日02:00。

示例：

```text
A团队：08:00–17:00
B团队：09:00–18:00

共同开始 = 09:00
共同结束 = 17:00
共享班次 = 09:00–17:00
```

## 3. 最终机器配置规则

计算共同班次后，最终输入机器的全部自动班次仍必须同时满足：

1. 每天最多3个自动班次、6个打卡时间点。
2. 使用24小时制。
3. 各自动班次不能互相重叠。
4. 打卡时间点不能重复。
5. 相邻两个自动班次之间必须至少间隔30分钟，即前一班下班与后一班上班之间至少间隔30分钟。
6. 班次设置后持续运行，不需要每月重设。

有效示例：

```text
第一班：08:00–12:00
第二班：12:30–17:30
第三班：18:00–20:30
```

无效示例：

```text
第一班：08:00–12:00
第二班：12:15–17:00
```

最终机器班次只间隔15分钟，不能保存为自动配置。客户需要调整为至少30分钟。

## 4. 处理流程

```text
识别员工团队及各自真实班次
→ 找出重叠时间段
→ 计算共同开始和共同结束
→ 告知客户机器不能直接输入重叠自动班次
→ 尝试用共同班次共享自动打卡栏位
→ 检查最终自动班次不重叠、不重复、至少间隔30分钟且不超过3班
→ 通过后设置02–08组
→ 不通过时调整时间、使用手动打卡或转人工
```

## 5. 菜单映射

- `02`组：`01/02/03`表示一、二、三个班次，`00`为手动打卡。
- `03/04`组：第一班上班/下班。
- `05/06`组：第二班上班/下班。
- `07/08`组：第三班上班/下班。

## 6. 客服回复模板

存在重叠但能形成共同班次：

> 亲，几组员工的真实时间有重叠，机器不能直接输入重叠的自动班次。我先按交集计算可共享的共同班次：共同开始取最晚上班时间，共同结束取最早下班时间。计算后还要确认最终机器班次互不重叠，并且每班之间至少间隔30分钟。

无法形成可用自动配置：

> 亲，这些时间计算共同班次后，仍然存在重叠、重复、间隔不足30分钟或超过3个自动班次，机器无法可靠自动定位。建议调整时间；如果实际排班必须这样交叉，请使用手动打卡模式。
